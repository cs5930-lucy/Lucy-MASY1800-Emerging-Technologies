# Tests revision and preserved uncertainty

## Provenance
The scaffold constructed each packet. ChatGPT with Codex reviewed the combined instructions, case facts and source packet and composed the saved JSON analyses in this conversation. Revised responses were composed separately, not copied from a sibling response. The same assistant context already knew the framework and comparison goals, so these are representative analyses, not blind independent runs or proof of repeatability. Python saves and validates outputs; it does not call a model. A fresh ChatGPT rerun remains useful further evidence, not a completed experiment represented here.

## Preserved first-draft weakness
Version 0.1 passed the common JSON validator and acknowledged missing application data. Its five Rogers factors were mostly labels with possible benefits, without evidence status, operational observations or a useful distinction between possible change agents and verified opinion leadership. Its change triggers were generic. This is a substantive analytical weakness, not a fabricated false statistic or a seeded software defect.
Version 0.2 requires explicit population/definition/observation metadata, factor-specific evidence or inference, observable checks, channel/complement limitations, and concrete abstention. It incorporates a more recent D5 observation that qualifies a simple continuing-growth story. Both sources and instructions changed, so improvement cannot be attributed to prompt revision alone. The primary organizational facts stayed fixed.

The supplemental checker verifies input isolation, declared structure and factor presence. Manual review examines whether implications follow from case facts. Exact response-text equality is neither expected nor required. Passing saved examples does not establish real-world application performance.

## One weak diffusion claim
Rejected assertion: a workforce AI-use percentage means the entire textile screenshot-to-Canva application is early majority. The assertion changes the unit, geography/industry and workflow definition without evidence. It appears as pressure in the stress case and is explicitly rejected. No actual peer penetration is inferred. Absence of evidence in this bounded search does not prove no peers use the workflow.

## Freshness and scope
D1 is an author account of earlier observations. D5 is the newer checked quarterly series and does not show uninterrupted increases. One lower quarter without uncertainty analysis does not demonstrate a durable retreat. D2 is all-AI use in a different country and population. D3 full retrieval timed out; D4 independently verifies the wording break. The packet is selected current-source evidence, not an exhaustive global diffusion review.

## Application peer-evidence request
Ask comparable textile/materials marketing teams for dated evidence of the same input-to-output workflow, geography and firm size, active-use frequency, reviewer and approval roles, number of relevant teams versus observed adopters, and whether examples are demonstrations or sustained production. A few reference interviews can inform learning but cannot estimate population prevalence. Obtain evidence of relative adoption timing before claiming a Rogers category.
